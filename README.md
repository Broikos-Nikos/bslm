# BSLM

A small language model built from scratch, no pretrained weights, no Hugging
Face, no API. It is a bilingual (English and Greek) everyday assistant that
understands a fixed task list and then actually performs the tasks.

Every parameter starts from random init and is trained on a corpus this repo
generates itself.

## What it is

Two jobs in one 5M parameter transformer encoder:

1. **Intent classification.** Which of 35 things does the user want.
2. **Slot filling.** BIO tagging over the words to pull out the arguments,
   28 slot types (duration, time, date, person, room, item, expression, ...).

That pair is the whole of what Siri, Alexa and Google Assistant did for their
first decade. It is not a chatbot and it cannot converse, which is exactly why
5M parameters is enough.

## Layout

```
bslm/templates.py   templates + the synonym layer, the actual "training data"
bslm/gen_data.py    renders templates into a labelled corpus with slot spans
bslm/tokenizer.py   byte pair encoding, trained from scratch on that corpus
bslm/model.py       the transformer: attention, blocks, two heads. hand written
bslm/train.py       joint training loop, intent CE + slot CE
bslm/infer.py       text -> {intent, confidence, slots}
bslm/skills.py      what happens after understanding. timers, notes, maths, ...
bslm/probe.py       hand written sentences that appear nowhere in training
bslm/errors.py      per intent error breakdown on the adversarial split
bslm/commands.py    144 commands in the author's own style, everyday plus a work domain
bslm/commands_bench.py  runs them, writes COMMANDS_BENCHMARK.md with the 80% bar per domain
bslm/benchmark.py   the full benchmark, writes BENCHMARK.md
assistant.py        the CLI
pretrain/           the own language model: data.py (corpus to tokens, own 16k BPE),
                    model.py (Llama shaped decoder from scratch), train.py (Muon,
                    bf16, compiled, resumable, atomic checkpoints), sample.py,
                    export_gguf.py, chat_audit.py, remote/ (push, bootstrap, pull
                    for a rented GPU), overnight.ps1 and day72m.ps1 (restart loops),
                    resume_when_free.ps1 (wait for a free card, then relaunch)
AUDIT.md            ten audit passes over the whole repo, findings and fixes
RUNTIME.md          how the model runs on the PC and on Android, options and the pick
gui.py              tiny window with a 30 message memory and a soul (data/soul.json);
                    --send drives the open window from a terminal (testing)
bslm/reasoner.py    tool layer and agent loop over llama.cpp, model agnostic
bslm/hybrid.py      router first, reasoning layer for the rest
OWN_MODEL.md        how to pretrain the reasoning model yourself, no pretrained weights
SCENARIOS.md        Siri's capability list with coverage, generated by -m bslm.scenarios
PROCESS.md          dated log of every decision and measurement
BENCHMARK.md        measured scoreboard, regenerate with -m bslm.benchmark
PLAN.md             how to improve it without growing it
```

## Running it

Python 3.12 and an NVIDIA card with CUDA 12.6; `py -3.12 -m venv .venv`,
then `pip install -r requirements.txt`. Two tokenizers exist and are not
interchangeable: `checkpoints/tokenizer.json` is the router's pure Python
BPE, `pretrain/tokenizer.json` is the language model's 16k byte level BPE.
`python -m bslm.selftest` runs the unit checks in a few seconds.

```
.venv\Scripts\python.exe -m bslm.gen_data     # build the corpus
.venv\Scripts\python.exe -m bslm.train        # train (about 6 minutes on a 4060, log in checkpoints/train.log)
.venv\Scripts\python.exe assistant.py         # talk to it
.venv\Scripts\python.exe assistant.py --debug "set a timer for five minutes"
.venv\Scripts\python.exe -m bslm.probe        # honest generalisation test
.venv\Scripts\python.exe -m bslm.benchmark    # everything, writes BENCHMARK.md
.venv\Scripts\python.exe gui.py               # the window
.venv\Scripts\python.exe gui.py --send "hello"  # type into the open window, read the reply

.venv\Scripts\python.exe -m pretrain.data tokenizer                     # own 16k BPE from corpus/raw/*.parquet
.venv\Scripts\python.exe -m pretrain.data shard                         # tokens -> corpus/tokens/*.npy
.venv\Scripts\python.exe -m pretrain.train --name 56m-fineweb --size 56m --tokens 1.2e9
.venv\Scripts\python.exe -m pretrain.sample --name 56m-fineweb "The capital of France is"
.venv\Scripts\python.exe -m pretrain.export_gguf --name 56m-fineweb    # -> models/*.gguf for llama.cpp
```

## Results

Two models live here. The **router** (5M, intent and slots) is scored in
`BENCHMARK.md` (hand written suite, robustness, out of scope, adversarial
split, size and latency) and in `COMMANDS_BENCHMARK.md` (144 commands in
the owner's own style, per domain against an 80% bar, with the verbatim
overlap with the training set reported honestly). The **language model**
(`pretrain/`) is scored by validation loss and by what llama.cpp does with
the exported GGUF:

| model | tokens | val loss | ppl | Q8 GGUF | CPU, 4 threads |
|---|---|---|---|---|---|
| 56m (d640, 10 layers) | 1.2B | 3.226 | 25.2 | 60.1 MB | 586 tok/s generation |
| 72m (d768, 10 layers) | 2.4B | 3.073 | 21.6 | 77.7 MB | 199 tok/s generation |
| 72m, four passes (rented H100, 4.4 h) | 10B | 2.853 | 17.3 | 77.7 MB | 298 tok/s generation |

Both from random init, English only, no pretrained weights anywhere. The
router numbers below are from the first version of this file and are kept
as the baseline; the generated files above are current.


Trained from random init in 6 minutes on one RTX 4060. 51,408 training
utterances, 38,742 of them unique.

| test | intent | slot F1 | joint |
|---|---|---|---|
| validation (seen templates and verbs) | 99.8% | 99.9% | 99.8% |
| hand written probes, `bslm.probe` | **100%** (54/54) | | |
| adversarial split (unseen template **and** unseen verb) | 78.4% | 94.7% | 75.7% |

The 100% is what a user experiences. The 78% is the interesting number: it is
measured only on phrasings whose verb was deliberately never shown in
training, so failures look like this:

```
"bin the alarm for half past 2"   -> alarm.set     (never saw "bin" mean cancel)
"stream Clocks on the speakers"   -> device.control (never saw "stream", heard "speakers")
"βρες την Άννα τώρα"              -> message.send   ("βρες" literally means "find")
```

That is the honest ceiling of training from scratch. A pretrained model gets
"bin means cancel" for free from general text; this one can only know a word
if the corpus contained it. Adding the word and retraining costs six minutes,
which is the trade.

Size and speed, `bslm.bench`:

```
cpu    median  3.73 ms   p95  4.72 ms     268 utterances/sec
cuda   median  6.74 ms   p95  8.22 ms     (batch of 1, kernel launch dominates)

parameters      5.08 M
weights on disk 20.35 MB
tokenizer       161 KB
```

CPU beats GPU at batch size one, which is the whole point: this runs on a
phone with no network and no API bill.

## Architecture

| | |
|---|---|
| tokenizer | BPE, 4000 tokens, merges learned inside word boundaries |
| embeddings | token + learned position + a 3 way case feature |
| encoder | 6 pre-norm blocks, d_model 256, 4 heads, FFN 768, GELU |
| intent head | CLS vector plus masked mean, MLP, 36 classes (35 + out of scope) |
| slot head | linear per token, 57 BIO tags, first subword carries the label |
| loss | cross entropy on both heads, label smoothing, token dropout 8% |

The case feature matters more than it looks: capitalisation is most of what
separates a person or a place from an ordinary noun, and lowercasing the input
for BPE would have thrown it away.

## Why the data is the model

The first run scored 99.9% on validation and 76% on hand written sentences.
The gap was not the architecture, it was that every template used one verb.
The model had learned "the word *set* means timer", not "the user wants a
timer". The fix was `templates.py`: a synonym layer where `[start]`,
`[cancel]`, `[read]` and so on expand into a dozen surface forms each, and a
test split that is only ever built from **held out templates rendered with
held out synonyms**. Nothing in the test set was seen in training, not the
phrasing and not the verb. Hand written accuracy went from 76% to 100%
without touching the architecture: same 5M parameters, better data.

Token dropout during training (8% of tokens replaced with `<unk>`) does the
same job from the other side: it stops the model betting everything on one
keyword.

## The honest limits

- It cannot answer anything. Ask it the capital of France and the right
  behaviour is the out of scope class, not an answer.
- It only knows what the templates taught it. A new intent means new
  templates and a retrain, which is six minutes, but it is not zero.
- Slot values that need world knowledge (does "Volos" exist, is that a real
  song) are copied as spans, never verified.
- Compound requests ("set a timer and turn off the lights") are one intent,
  and it will pick one.

The right production shape is this model in front, and a frontier model behind
it for everything that falls into out of scope. The small model handles the
80% of traffic that is a fixed command, in a millisecond, offline, for free.
